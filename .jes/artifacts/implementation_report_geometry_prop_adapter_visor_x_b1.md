## Documented choice (IC §3 P2 / §0 lock #4: "document actual")

`prop_adapter` follows the **propeller pattern**, not the stricter `frame_arm` one: any valid cross-read count in `[2,16]` gets `solidCopies` (a plain row when the quad-X gate doesn't hold), never omitted entirely for N≠4. Rationale, per the IC's own preference ("prefer propeller pattern... unless a one-line conflict forces arm-strict"): one adapter per motor is a genuinely honest fallback shape for any N — unlike an arm, whose entire reason for having N copies is standing at N specific quad-X stations, an adapter is just "N of the same small part, one per motor," which a plain row represents fine even without station geometry. No conflict was found forcing the arm-strict gate, so the propeller pattern was used as preferred (verified, P2: N=3 → `solidCopies==3`, no offsets, never a fake 3-station X).

## Behavior changed

- A `prop_adapter` with a declared box now gets `solidCopies` cross-read from the sibling `motors` spec's own `motor_count` — 4 on the live 5min project (verified live below), matching motors/propellers/frame_arm exactly.
- When that count is exactly 4 **and** the frame declares `quad_x` + a finite positive `wheelbase_mm`, the adapter also gets `solidCopyOffsetsMm` — byte-identical to motors' own station points (verified, P1 and P5's cross-family comparison).
- Any other count (e.g. 3) still gets `solidCopies` (a plain row), but never fake X-station offsets (P2).
- No adapter geometry → no `solidCopies`/`solidCopyOffsetsMm` at all, exactly as every other family already behaves (P3).
- Still exactly **one** `prop_adapter` `ComponentSpec`/BOM/card node (P4) — copies are visor-only, generated by the already-existing, unchanged `expandSolidCopies` mechanism.
- The previously "wrong product" single FR-stand-in pose (`prop_adapter.declaredBoxPose` vs `frame_plate`, ~(81,81,16)) is now visually superseded in the 3D visor: `expandSolidCopies` already strips `declaredBoxPose` on any node with `solidCopies>=2` (pre-existing, unchanged behavior) — verified live, the card's DTO still carries the raw pose text field (per lock #5, "Engineer may clear the orphan FR pose or leave it"), but the visor draws the honest 4-station X instead of one box parked at the FR corner.
