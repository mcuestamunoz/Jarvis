## Files changed

- `src/jarvis/schemas/action_schema.py` — **§3.1**: new `DeclaredBoxPose(BaseModel)` (`origin_key: str`, `x_mm`/`y_mm`/`z_mm: float | None = None`), with a docstring stating the origin-point/axes honesty discipline verbatim (geometric center of a declared box; axes are Jarvis-**declared**, not sourced — every seeded box's own `source_note` says its L/W/H order is "verbatim print order," cited by file reference to the investigation). `ComponentSpec` gained `declared_box_pose: DeclaredBoxPose | None = None`, placed immediately after `mounted_on`; the `mounted_on` field's own comment was extended with one line noting pose now lives in this separate, orthogonal field.
- `src/jarvis/core/component_writers.py` — **§3.2**: new `set_component_declared_box_pose(project_state, component_key, pose)`. `pose=None` clears (idempotent — returns the same `project_state` object, unchanged, when already `None`, confirmed by `test_t5b`). A non-`None` pose is validated in order: `component_key` must exist (`ValueError` otherwise); `pose.origin_key` must differ from `component_key` (no self-origin); `origin_key` must exist in `components`; and `origin_key`'s spec must resolve to `{"shape": "box", ...}` via `_geometry_from_spec` (imported locally from `jarvis.workspace.spatial_board`, confirmed no circular import both by static analysis and a live import test) — a disk or a shapeless spec raises `ValueError`, reusing the exact same box-detection rule the projector and CSS 3D layer already use, never a second one.
- `src/jarvis/workspace/spatial_board.py` — **§3.3**: `_fields` signature widened to `_fields(spec, components)` (its one call site, inside `place()`, updated to pass the closure's `components` dict). New module-level `POSE_AXES_HONESTY_LABEL = "locales declarados (L→+X, W→+Y, H→+Z); no morro; no gravedad"` constant. When `spec.declared_box_pose` is set **and** its `origin_key` is still present in `components`, `_fields` appends `"origen pose"` (the origin key), `"ejes pose"` (the honesty label, verbatim, every time — never a variant), and `"Δx mm"`/`"Δy mm"`/`"Δz mm"` only for the offsets that are not `None`. When the origin key has vanished, the whole pose block is omitted — confirmed live (not just by code inspection) that this doesn't crash and produces an empty `fields` list for that case, the same "honest absence, no fallback origin" discipline B2's own `mountedOn` DTO key omission already established. A small `_format_number` helper trims whole-number floats the same way this session's other numeric-text helpers already do (e.g. the catalog-refresh diff copy), kept separate from `_format_property` since it operates on a bare float, not a `PropertyValue`.
- `tests/test_geometry_pose_declared_box_frame_b1.py` (**new**) — 9 tests covering T1–T6 exactly (T1 round-trip + Board fields; T2 reject shapeless origin; T3 reject disk origin; T4 + two extra guards — missing origin key, self-origin, and missing `component_key` itself; T5 + an idempotent-clear guard; T6 catalog-refresh preservation). T7 (full-suite non-regression) is exercised by running the whole suite, not a dedicated test file, per the IC's own framing of T7 as a suite-wide check rather than a new test.

## Behavior changed

- A component can now declare a millimetre offset (`x_mm`/`y_mm`/`z_mm`, any subset) relative to another, box-having component's own geometric center, via `set_component_declared_box_pose`. This is purely additive — confirmed live (§ below) that setting it on a synthetic ESC→FC pair produces exactly the four expected text fields, no more, no fewer, and that `geometry`/glyph/3D-solid behavior for that node is completely unaffected (the ESC in the test fixture has no box props of its own, and its `geometry` stayed `None` throughout).
- The writer correctly rejects every dishonest origin candidate this IC named: `frame_plate` (shapeless — reuses `_geometry_from_spec`, returns `None` since no L×W is sourced for it), `motors` (a `disk`, rejected per the origin/axes investigation's own §A3 finding that rotational symmetry has no in-plane heading), a missing key, and self-reference — all four confirmed live with real `ValueError` messages, not just asserted in tests.
- Board text now shows the pose block, when set, with the **exact** honesty label locked by the IC — verified this is not paraphrased or shortened anywhere, appears identically every time regardless of which offsets are present.
- `refresh_component_from_catalog` preserves `declared_box_pose` across a catalog refresh — confirmed via `test_t6`: refreshing a stale-mass ESC (26g→15g) leaves its `declared_box_pose` byte-identical, because `bind_esc_from_catalog(sku, base=spec)`'s `model_copy` only overwrites `properties`/`completeness`/`catalog_ref`, exactly the same mechanism that already preserves `mounted_on` across a refresh (no new preservation logic was written — this is the same `base=` merge this whole geometry axis has relied on since the catalog-bound-refresh IC).
- `Scene3D.tsx`, `scene3dLayout.ts`, `scene3dScale.ts`, `Solid3D.tsx` — confirmed **byte-identical**, `git diff` empty for all four. No `layoutSolidsRow` input changed, no CSS 3D solid moved by this IC's numbers, exactly as locked.
- No Continuity assist file added or touched — there is still no IDLE phrase that can set a pose; this field is reachable only via direct writer calls (scripts/tests/a future, separately-Bought Continuity IC), the same sequencing already used for the `mounted_on` relation itself (schema+writer+Board text shipped before Continuity did, one cycle at a time).

## Remaining risk / notes for review

- `declared_box_pose` is reachable only programmatically today (writer calls from tests/scripts, or a future Continuity IC) — this is the same, already-established sequencing gap the `mounted_on` relation itself had for one cycle (Continuity declare shipped as its own, separate, later IC) — named here for the same reason, not a defect in this cycle's scope.
- The honesty label (`POSE_AXES_HONESTY_LABEL`) is a single, fixed string shown identically for every pose regardless of which origin or which offsets are declared — this was a deliberate simplicity choice (one honest sentence, never a per-origin variant that could drift or be forgotten for a future box-having family) rather than an oversight; easy to extend later if a future cycle wants per-family nuance.
